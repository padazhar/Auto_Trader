# P05 — IMPLEMENT EXACTLY ONE APPROVED STEP (REUSABLE FOR S01…SN)

**Inputs set by operator:** `STEP_ID = S__`; `PLAN_VERSION = __`; `REPO_ARTIFACT = __`; latest P06 validation if any; attached approved trackers, previous updated full repo, baseline hashes and test evidence.

**Mode: IMPLEMENT ONE STEP, OFFLINE ONLY unless separately authorized by its plan gate.**

Read the GLOBAL CONTRACT and the approved step verbatim from the versioned plan. Reopen and hash the *latest* full repository, not the initial ZIP when newer code exists. Cross-read every affected upstream producer, downstream consumer, model/feature contract, type/schema, risk and execution path, manifest, config, cache, monitoring publisher, tests and documentation. Verify expected code and config signatures match the plan before editing. If the current checkout is different, if a required artifact is missing, or if the step would require out-of-plan work, do **not** improvise: open `CR-###`, show the discrepancy and stop for Auditor approval unless it is explicitly within the permitted step scope.

**Before code:** Provide a concise change inventory: exact current files/functions (verified); failing behavior/test oracle; desired invariants; API/config/schema/runtime behavior; dependency and migration effects; security/economic side effects; tests and negative cases; compatibility and revert plan; whether affected models must be retrained, existing states migrated, paper/testnet trials repeated, telemetry/dashboard verified. Identify downstream files even if unchanged, with an explicit rationale for retaining them.

**Implement completely, not cosmetically:** Fix the proven root cause and dependent consumers within the step. Write actual production code and assertions, not TODOs/placeholders/mock-only fixes. Ensure atomicity/durable persistence where needed, restart/retry behavior, clear error types and fail-closed safeguards. Update negative regression tests that enshrine incorrect legacy behavior; add tests for failure-before/success-after, happy/edge/exception paths and any applicable paper/live parity. Use deterministic local fixtures; do not rely on live API for unit tests. Never weaken validation thresholds or delete tests to make a step green. Never activate a production endpoint, production key, network order route or auto-trader while the integrated execution gate remains closed. If a step changes external economic semantics, demonstrate recovery/abort without loss of exchange-authoritative state.

**Run validation that is safe NOW:** syntax/type/import/test collection, focused affected tests, compatible regression suite, offline integration and fault injection appropriate for STEP_ID. Save exact commands, exit codes and logs; run pre- and post-change tests if safe and feasible. If any test needs dependencies/data not present, label `NOT_RUN / BLOCKED` rather than `PASS`. Document missing evidence and whether this step is ready for P06. Do not claim that paper/testnet/production gates passed during an offline code step.

**Package (if tooling permits):** `Auto_Trader_after_<STEP_ID>_<hash>.zip` including the **complete updated repository** with its original directory structure; `diff_<STEP_ID>.patch`; `CHANGELOG_<STEP_ID>.md`; `TESTS_<STEP_ID>.md`; updated finding/step/coverage trackers; `CR` log and file manifest/hashes. No secrets, private keys or unnecessary real-account state. If unable to produce a complete ZIP, explain exactly which files could be changed and do not claim to have delivered a working artifact. Avoid pasting huge entire source trees into the chat when a verified complete ZIP is available.

**End with:** `IMPLEMENTED_AWAITING_INDEPENDENT_VALIDATION`, `IMPLEMENTATION_FAILED`, or `BLOCKED_BY_EVIDENCE`, listing unresolved items and specific risk. **Do not implement or start any subsequent step.**
